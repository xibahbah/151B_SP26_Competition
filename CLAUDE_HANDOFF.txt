Common OOM Pattern
==================
If vLLM throws CUDA OOM during `LLM(...)`, another Python/vLLM process is usually still holding GPU memory.

Check:
  `nvidia-smi`
  `ps aux | grep python | grep -v grep`

Kill stale GPU process:
  `kill <PID>`
  `sleep 5`
  `nvidia-smi`

If needed:
  `kill -9 <PID>`

Do not run notebook UI and remote `nohup` inference at the same time.

What Each Script Does
=====================
`scripts/run_private_submission.py`
  Best current private submission path.
  Runs MCQ private inference, then FRQ private inference, repairs FRQ outputs, merges predictions, and writes:
    `submission.csv`
    `results/submission.csv`
    `results/private_run/private_predictions_merged.jsonl`
  CSV column format is exactly `id,response`.
  The response is full raw model trace plus final repaired boxed answer when available.

`scripts/eval_mcq_vllm.py`
  MCQ-only vLLM inference/eval.
  Uses baseline MCQ prompt and settings.
  For private data, produces unscored predictions.
  Do not casually change MCQ settings.

`scripts/eval_frq_vllm.py`
  FRQ-only vLLM inference/eval.
  Uses concise FRQ prompt.
  On public data, scores with `Judger`.
  On private data, no gold answers, so it writes unscored predictions and postprocessed answers.
  Supports `--sample-size`, `--ids-file`, `--max-tokens`, `--batch-size`, `--lora-path`.

`scripts/repair_frq_outputs.py`
  Deterministic FRQ repair/postprocess/templates.
  Public-safe selected repair chooses candidates using heuristics, not gold answers.
  On public data it can report selected accuracy and oracle ceiling.
  On private data it only repairs and marks rows as unscored.

`scripts/summarize_frq_results.py`
  Summarizes FRQ JSONL accuracy/error types for public result files.

`scripts/analyze_frq_errors.py`
  Groups errors and helps decide what templates to add next.

`scripts/prepare_external_math_sft.py`
  Pulls external math data and formats it for SFT.
  Previous OpenR1 / external LoRA tests did not beat baseline.

`scripts/train_lora.py`
  LoRA/QLoRA training script.
  LoRA experiments so far were not useful enough; template repair is currently better.

`scripts/prepare_self_distill_sft.py`
  Creates self-distill data from solved public FRQ.
  Self-distill LoRA also did not beat baseline.

`scripts/select_best_frq_candidates.py`
  Used for multi-generation candidate selection experiments.
  The multigen experiment was slow and not worth continuing unless redesigned.

Accuracy / Experiments So Far
=============================
Useful baseline:
  Full public FRQ, 4096 tokens + v11 repairs:
  about `620/751 = 82.56%`.

Earlier repair progression:
  v6: `544/751 = 72.44%`
  v10: `579/751 = 77.10%`
  v11: `620/751 = 82.56%`

6144-token full FRQ run:
  Worse than 4096.
  Around `422/751 = 56.19%` before later repairs.
  It took about 8.5 hours and did not help.
  Do not use 6144 by default.

LoRA experiments:
  Public-only LoRA overfit/failed.
  OpenR1 solution LoRA failed.
  Self-distill safe LoRA failed on holdout.
  Current advice: do not rely on LoRA unless a new carefully controlled experiment proves it beats 4096+repair on a held-out set.

Multigen experiment:
  Generated 3 candidates for wrong IDs but output quality/selection was poor and runtime was high.
  Not the current best path.
